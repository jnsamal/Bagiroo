# Setup Guide

## Prerequisites
- Node.js 18+
- MySQL 8+
- npm 9+

## 1. Install dependencies
```
npm install
```
(npm workspaces installs `client`, `server`, and `shared` together.)

## 2. Configure environment
```
cp .env.example server/.env
```
Fill in at minimum:
- `DATABASE_URL` — your MySQL connection string
- `JWT_SECRET` / `COOKIE_SECRET` — any long random strings for dev
- `SMS_PROVIDER=console` — leaves OTPs printed to the server console in dev
- `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` — only needed once checkout (Phase 4) is implemented

## 3. Create the database schema
```
npm run db:migrate -w server
```

## 4. Seed development data
```
npm run db:seed -w server
```
This loads the real 8-product catalogue (from the client's WooCommerce export) with real descriptions, pricing, and photography — the images already ship in `/uploads/products` in this zip, so no extra asset step is needed. `server/prisma/image-manifest.json` maps each SKU to its image set; re-running the seed is safe (it upserts).

## 5. Run the app
```
npm run dev
```
- API: http://localhost:4000 (health check at `/health`)
- Client: http://localhost:5173 (Vite dev server proxies `/api` to the server)

## OTP login in development
With `SMS_PROVIDER=console`, requesting an OTP prints the code to the **server** terminal instead of sending a real SMS. Use that code on the verify step.

## Troubleshooting

**Images not loading / broken image icons everywhere**
Fixed in this update — product/category images and the hero image are stored as relative paths (`/uploads/...`) that only the API server can resolve, not the Vite dev server. The client now prefixes these correctly, and `vite.config.js` also proxies `/uploads` to the API as a fallback. If you pulled this update into an already-running dev server, restart `npm run dev` so the new Vite config takes effect.

**Best Sellers / New Arrivals / Shop by Category sections empty or missing**
These all come from one endpoint (`GET /api/v1/homepage`) that queries several tables at once — if any single part of that query fails (most commonly: the database schema is out of sync with `schema.prisma`), the *whole* homepage request fails, taking every section down together, not just one. If you see this:
1. Check your server terminal for a Prisma error when you load the homepage.
2. Re-run, in order: `npm run db:migrate -w server`, then `npm run db:seed -w server`.
3. Restart `npm run dev` afterward (Prisma Client is regenerated by `migrate`, but a running Node process won't pick that up until it restarts).

**Can't go back after visiting a page**
Fixed in this update — one product card button was using a hard page reload (`window.location.href`) instead of normal in-app navigation, which is the kind of thing that makes browser back/forward behave inconsistently. It now navigates the same way as every other link in the app. The overall routing structure was also simplified (single shared layout instead of a nested-router pattern) to remove any doubt.
